# Rhēma Deep Lexicon — Stage 1 (deterministic evidence)

Generated by `node scripts/build-deep-lexicon.js` from data already shipped
with the app. No network access, no AI — every number in every entry can be
recomputed and checked against the cited verses.

## What this is

An evidence-backed range of meaning for every Greek Strong's number, built the
way a lexicographer works but with exhaustive coverage:

1. **Translation alignment.** A statistical word-alignment model (IBM Model 1
   with a NULL token, 8 EM iterations) is trained between the Byzantine
   New Testament (Robinson–Pierpont 2018, `rhema-nt.js`) and the **Majority
   Standard Bible** — an English translation made from that same Greek text.
   Every occurrence of every Greek word receives an attested English
   rendering with a verse citation, or is classed as "absorbed" when the
   English phrasing gives it no word of its own.
2. **Independent cross-check.** The same model is trained against the
   **Berean Standard Bible**; each sense records how often the BSB
   independently agrees with the MSB rendering.
3. **Sense grouping.** Renderings are normalized (stemming, edge
   function-word trimming) and grouped into senses, ranked by frequency,
   each carrying count, share, citations, and corroboration flags against
   the Dodson, Strong's, and KJV gloss lists.
4. **Septuagint evidence.** A second alignment model over the LXX
   (`rhema-lxx.js`) and the Hebrew OT (`rhema-ot-hebrew.js`) yields the
   Hebrew words each Greek word translates — e.g. λόγος ← דָּבָר (698×).
5. **Other evidence.** Byzantine-vs-critical-text (SBLGNT) occurrence
   deltas, syntax-role distribution (Macula), and Moulton–Milligan
   documentary (papyri) flags.
6. **Confidence + explanation.** Each entry gets a confidence tier
   (high / good / moderate / low / none) and a generated "why this
   definition" walkthrough derived purely from the numbers above.

## Files

- `spine.json` — tiny (~210 KB): `strongs → [lemma, top gloss, NT count,
  confidence]`. Suitable for shipping with the app for instant lookups.
- `shard-NNNN.json` — full entries, 100 Strong's numbers per shard
  (~7 MB total uncompressed, ~5–8× smaller over gzip). Designed for
  on-demand fetch + Cache API so the app never loads all of it at once.
- `index.json` — shard manifest and build metadata.
- `report-sample.md` — human-readable sample entries for spot-checking.

## Entry shape

```js
{
  "s": 3056, "lemma": "λόγος", "translit": "lógos",
  "count": 331,                    // Byzantine NT occurrences
  "refs": ["MAT 5:32", ...],       // example citations
  "byBook": { "MAT": 32, ... },
  "senses": [{
    "key": "word",                 // normalized sense key
    "display": "word",             // most common attested rendering
    "count": 198, "share": 0.84,   // share of translated occurrences
    "refs": ["MAT 7:24", ...],     // verifiable citations
    "bsbAgree": 1.0,               // independent BSB agreement
    "corroborated": ["dodson","kjv"],
    "variants": { "word": 190, ... }
  }],
  "rare": [...],                   // singleton renderings with citations
  "untranslated": 95,              // occurrences absorbed into phrasing
  "lxx": { "count": 961, "books": 36, "refs": [...],
           "hebrew": [{ "h": 1697, "lemma": "דָּבָר", "count": 698 }] },
  "critical": { "count": 330 },    // SBLGNT occurrences
  "syntax": { "s": 12, "o": 40 },  // role distribution (Macula)
  "mm": true,                      // Moulton–Milligan papyri evidence exists
  "confidence": "high",
  "why": ["…", "…"]                // generated explanation, one claim per line
}
```

## Honest limits (read before trusting an entry)

- **Translation choice ≠ meaning.** A consistent English rendering can hide
  real polysemy, and stylistic variation can fake it. The senses here are
  *attested renderings*, which approximate — but are not identical to —
  semantic senses.
- **Alignment is statistical.** IBM Model 1 has no word-order model; rare
  idioms (e.g. συναίρω λόγον "settle accounts") sometimes land in the
  "absorbed" bucket instead of yielding their sense. Per-sense BSB agreement
  and citations exist precisely so any claim can be checked.
- **Low-count words.** For words with a handful of occurrences the corpus
  numbers carry little weight; the confidence tier says so explicitly, and
  the classical lexica (Abbott-Smith, Dodson, Moulton–Milligan) shipped with
  the app should dominate.
- **Versification.** Verses absent from either side of a pairing are skipped;
  LXX↔Hebrew alignment inherits known versification offsets (Psalms etc.),
  which wash out statistically but can distort individual rare counterparts.

Stage 2 (planned) layers a reviewed synthesis pass over this evidence to
produce prose definitions; Stage 3 wires the shards into the app via
on-demand loading.
